# Mix Atlas — ミックス品質可視化・比較ツール

Windowsで動作するローカル解析アプリの初期実装です。ボーカル・ドラム・ベースの相対音量、帯域競合、低域、トランジェント、M/Sをリファレンスと比較します。品質の合否や自動補正量を断定するツールではありません。

## 起動

この作業環境では依存関係のセットアップ済みです。`start.cmd`をダブルクリックするか、このフォルダーで以下を実行します。

```powershell
npm.cmd start
```

初めて別の環境へ配置する場合は、Windows x64、Python 3.13、Node.js 22以上を用意し、PowerShellで実行します。

```powershell
.\setup.ps1
```

スクリプト実行ポリシーで起動できない場合は、そのPowerShellプロセスに限定して実行します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
```

`setup.ps1`は、このフォルダー内の`.venv`へPython依存関係を、`node_modules`へElectronをインストールします。Pythonは`requirements-lock.txt`、Nodeは`package-lock.json`に固定したバージョンを使用します。PythonやNodeのグローバル環境は変更しません。

現時点では開発用の起動形式です。Python同梱の配布用EXE／インストーラーはまだ作成していません。

## 使い方

1. 「解析する音源」でWAV・FLAC・MP3のミックスを選びます。
2. 解析方法を選びます。
   - **自動分離**：ボーカル／ドラム／ベース／その他へ分離して解析。既定は精度優先のHT Demucs FT。標準モデルHT Demucsも選べます。
   - **入力ステム**：4パートを手動指定。ミックスと同じ開始位置・長さ・サンプルレートで書き出してください。存在しないパートは同じ長さの無音ファイルを指定します。
   - **元音源のみ**：分離せず、帯域・低域比率・密集度・M/Sだけを解析します。パート別指標は対象外になります。
3. リファレンスの「＋」で、比較する音源を同様に追加します。複数曲を追加できます。
4. タブを切り替えて特徴を確認します。カードは選択区間の中央値、差分は各リファレンス曲の区間中央値を等重みで集約した値との差です。
5. 開始秒・終了秒を入力して区間を指定できます。リファレンスの「表示・区間指定」で解析対象と入れ替え、曲ごとに近い編成の区間を選びます。指定は曲ごとに保持します。
6. 下部のプレイヤーで曲と成分を選び、再生します。時間グラフ・ヒートマップのクリックで解析対象の該当時刻へ移動します。
7. 「保存済みの解析を開く」で再利用、「解析をエクスポート」で測定系列と比較区間をJSONへ保存できます。

モデル取得後の音声処理はローカルです。初回のみモデルをダウンロードし、音源の送信は行いません。

### CPU / NVIDIA GPUの選択

自動分離の読み込み画面にある「分離デバイス」で選択します。選択は次回起動時も保持します。

- **自動（GPUを優先）**：CUDAが利用できれば最初のGPU、利用できなければCPU。
- **CPU**：GPUがあってもCPUで分離します。
- **GPU：機種名**：指定したGPUで分離します。複数GPUがあればそれぞれ選べます。

GPUを使うのはニューラルネットによる音源分離です。デコード、帯域・M/S・トランジェント等の数値解析はCPUで行います。入力ステムと元音源のみのモードではGPU選択は不要です。

CUDA版PyTorchがない環境では、通常のセットアップ後に次を実行してください。公式PyTorchのCUDA 12.8版をプロジェクトの`.venv`に導入します。NVIDIAドライバーや他のPython環境は変更しません。ダウンロードは約3.5GBです。

```powershell
.\setup-cuda.ps1
```

導入後はアプリを再起動します。左下にCUDAのバージョンと検出したGPU名が表示されます。CUDA対応のPyTorchはCPU実行も可能です。既存のCUDA版がある場合、通常の`setup.ps1`で指定する`torch==2.8.0`の条件も満たすため、CPU版へ置き換える必要はありません。

GPUを明示指定した場合、利用不能やメモリ不足を黙ってCPUへ切り替えません。画面に理由とCPUへの変更方法を表示します。「自動」でも分離中のGPUメモリ不足はエラーとして扱います。CPU/GPUの数値結果には微小な差が出る場合があります。

キャッシュは実際のデバイスとPyTorchのビルドごとに分けます。CPUからGPUへ変更した最初の解析は再分離し、次回以降はGPU側のキャッシュを使用します。自動とGPU明示指定で実行先が同じ場合はキャッシュを共有します。結果の見出しには実際に分離したデバイス名とキャッシュ使用を表示します。

速度比較は、合成デモを生成した後に次で実行できます。解析・分離キャッシュを使わず、同じ12秒の音源を同じモデルでCPU/GPU各1回処理します。モデル読み込みを含む分離時間を測り、後段の数値解析は含めません。

```powershell
.\.venv\Scripts\python.exe -m scripts.benchmark_devices
```

結果は`.data/device-benchmark.json`へ保存します。短時間の単発比較であり、実曲全体の所要時間を保証するものではありません。

このPCのRTX 3080（12GB）では、12秒の合成音源・HT Demucs FTでCPU 26.98秒、GPU 4.21秒でした（分離工程で約6.4倍、PyTorch 2.8.0 / CUDA 12.8）。

導入するビルドは[PyTorch公式の過去バージョン一覧](https://pytorch.org/get-started/previous-versions/)の2.8.0 / CUDA 12.8です。

### 分離後の解析時間

入力は44.1 kHzへ変換してから解析するため、48 kHz入力によって分離後の計算量が増えることはありません。24 bit入力も読み込み後は同じ浮動小数点形式です。曲が長いほど、4パートとそれ以外の信号の帯域・M/S・音量計算、試聴ファイルの保存量が増えます。

400 ms／3秒の音量窓で共通のK特性フィルター処理と累積パワーを再利用し、FFT用フレームの配列コピーと結果整形の負荷を削減しています。解析サンプルレート、FFTサイズ、時間間隔、閾値、丸め方は変更していません。既存の解析・分離キャッシュもそのまま利用できます。

このPCの472秒（7分52秒）の合成4ステムで、変更前75.56秒→変更後53.35秒（約29%短縮）、出力全項目の完全一致を確認しました。各1回の数値解析のみの比較であり、分離・デコード・試聴WAV保存は含みません。ユーザーの実曲の計測ではありません。計測結果は`.data/dsp-benchmark.json`へ保存しています。

## 画面と指標

| タブ | 主な表示 |
| --- | --- |
| 概要 | 声・ドラムの相対音量、低域比率、Side比率、帯域分布 |
| ボーカル | K特性の相対音量、ステレオ／Mid内／Side内の帯域競合 |
| ドラム | 相対音量、立ち上がり時間、アタック／ボディ比、減衰、クレスト、イベント散布図・包絡 |
| ベース・低域 | ベース相対音量、低域・サブ低域比率、パート別低域構成、−23 LUFS換算の低域パワー |
| M/S・音像 | Side比率、Side/Midレベル、相関、左右差、帯域別Side比率／モノラル合成差／左右相関、M/Sスペクトル |
| 密集度・競合 | 時間・周波数の占有度、分離パート間の競合、スペクトル |

- パート相対音量は同一時間窓のK特性エネルギー比。400 msと3秒の推移を切り替えられます。
- 帯域解析は44.1 kHzへリサンプルし、4096点Hann窓、50 ms間隔、32 ERB帯域を使用します。低域の集計は20–60、60–200、200–500、500–2000、2000–6000、6000–20000 Hzの別バンクです。
- 比較する音源で元の周波数上限が異なる場合、そのリファレンスを数値比較から除外します。
- 低域・M/S比率は重み付けなしのパワー比で、知覚的な音量・広がりの割合ではありません。無音や比率の測定不能値は`—`と表示します。
- Mid/Sideは`(L±R)/sqrt(2)`。モノラル試聴は`(L+R)/2`を左右に同じ音で出力します。この規約では「Midのみ」と「モノラル」は同じ音です。Sideのみは左右逆極性で復号します。
- 試聴には16-bit PCM WAVを使用します。クリッピングを避けるため必要な場合のみ、その曲の全成分へ同一ゲインを適用します。画面に補正量を表示し、曲間の自動音量合わせは行いません。解析は元の浮動小数点データを使用します。
- M/Sスペクトル、帯域構成、パート別低域構成、活動時間率は曲全体の補助集計です。カード・時間系列・ヒートマップ・イベント集計は選択区間を使います。
- リファレンスの時間系列は比較区間を0〜100%へ対応させます。拍・歌詞・楽曲構造の自動整列はしません。

## 試作指標の制約

指標の数値計算とUIの動作を検証していますが、実際の歌唱曲を使った聴感評価・閾値調整はこれからです。

- 歌唱／活動区間はエネルギーゲートによる暫定検出です。歌声認識モデルは未実装です。ボーカルタブで自動検出の対象を手動の歌唱区間に絞れます。自動検出で除外された値の復元は未実装です。
- 帯域競合は「対象の有効帯域で、他パートのパワーが上回る割合」です。聞き取れない確率や心理音響的なマスキング閾値ではありません。
- 密集度は全曲を−23 LUFSへ換算した場合に、各ERB帯域が−55 dBのパワー閾値を超える割合です。無音は対象外。単独の広帯域音でも高くなります。
- パート競合は、各有効帯域で最大パートから12 dB以内に複数パートがある割合です。4分離の「その他」内部は分析できません。
- 打音の検出は包絡の正方向変化と局所ピークを使う試作方式です。キック／スネア等の分類と拍同期のビート強度は未実装です。
- アタック／ボディ比は0–30 msと50–150 msの平均パワー比です。150 ms以内の重複打音は通常集計から除外します。減衰は20 dB低下を10 ms保持した時点までとし、500 ms／次の打音／背景ノイズで観測が打ち切られます。測定可能数を併記します。
- 4パート分離は推定です。元ミックスとステム合計が異なる場合、警告します。マスターコンプレッションが掛かった完成音源と、掛かっていない入力ステムなども差が出ます。
- M/S内の帯域競合は空間的マスキングを完全には表しません。モノラル合成差とSide比率には数学的な重複があります。
- モノラル入力はL/Rへ複製し、他の入力と同じステレオ解析経路を使います。表示ラウドネスもこの複製後の測定です。
- 区間指定は保存済みフレームの選別です。境界付近の窓は区間外のサンプルも含みます。
- 音源はメモリへ読み込むため、長時間音源は曲単位に分けてください。配信ライブなど数時間の解析は未検証です。

### ボーカルの手動区間指定

ボーカルタブの「ボーカルの集計対象区間」で開始・終了秒を入力し、複数区間を追加できます。重なる区間は統合します。各区間の開始を含み、終了を含まないフレームを採用し、比較区間との共通部分だけを集計します。カード・時間グラフ・Stereo／Mid／Sideの競合ヒートマップ・リファレンス比較に反映します。その他のパートや曲全体の自動活動率は変更しません。

設定は解析結果IDごとにローカル保存し、履歴の再読み込みやアプリ再起動後も復元します。リファレンスは「表示・区間指定」で表示を入れ替えて編集します。JSONエクスポートの`vocal_ranges`にも保存します（元の数値系列は保持）。指定区間をすべて削除すると対象なしになり、「自動検出に戻す」で元の集計へ戻ります。

これは自動検出結果を絞り込む機能です。無音や自動ゲートで除外された値を復元する機能ではありません。分離・数値解析の再実行は不要で、境界付近の解析窓は指定区間の外を含む場合があります。

### ドラムの帯域別イベント

ドラムタブの「打音の解析帯域」で全帯域・低域（20–200 Hz）・中域（200 Hz–2 kHz）・高域（2–20 kHz）を切り替えます。打音カード、測定状況、散布図、包絡、リファレンスの打音指標が連動し、区間指定も反映します。ドラム相対音量と帯域競合は従来どおり全帯域の指標です。

帯域別は2次Butterworthバンドパス設計の因果SOSフィルター後に独立検出します。非ドラムにも同じフィルターを適用して相対レベルを測ります。低域の周期やフィルターの遅延・リンギングを含むため、帯域間の時間差を演奏タイミングの差とは解釈しません。同じ打音が複数帯域で検出される場合があり、件数は合算しません。元音源の周波数上限が帯域上端に届かない帯域は対象外です。帯域名は楽器名ではありません。

追加処理に伴い解析バージョンを0.1.0-9に更新しました。新規の数値解析には帯域別処理時間が加わります。分離ステムは再利用でき、既存の全帯域の指標定義は変更していません。

## キャッシュとファイル

- `.data/models/`：Demucsのモデル。FTは4モデル、標準は1モデルを取得します。
- `.data/separated/`：再利用可能な浮動小数点ステム。解析アルゴリズムの変更後も再分離を省けます。
- `.data/analyses/`：解析JSONと試聴WAV。入力内容のSHA-256、モード、モデル、解析バージョンで識別します。自動分離時は実行デバイスとPyTorchビルドも識別に使います。
- `.data/desktop/`・`.data/session/`：Electronのローカル設定・キャッシュ。
- `.cache/`：依存関係のダウンロードやテスト用ファイル。
- `demo-audio/`：自作の合成音源。実際の歌唱の分離精度評価には使えません。

元音源は変更しません。解析履歴には現在の解析バージョンの結果だけを表示します。モデルやキャッシュの自動削除は行いません。試聴WAVと分離ステムは曲の長さに応じてディスクを使用します。

## 開発・検証

```powershell
npm.cmd run demo        # 合成した対象曲とリファレンスを生成
npm.cmd run test:audio  # DSP・読み込み・キャッシュのテスト
npm.cmd test            # Electronの操作・試聴テスト
node --test tests/vocal-ranges.test.cjs # 歌唱区間の検証
.\.venv\Scripts\python.exe -m scripts.smoke_separation  # FT実モデルの短時間スモークテスト
```

スモークテストは初回にモデル取得のネット接続を使います。UIテストはファイル選択ダイアログの返り値のみを置き換え、実際のPython解析・IPC・音声再生を確認します。

| ファイル | 役割 |
| --- | --- |
| `backend/analysis.py` | DSP・集計・トランジェント |
| `backend/worker.py` | デコード・分離・キャッシュ・JSONプロトコル |
| `desktop/main.cjs` | Electron・ファイル選択・子プロセス・ローカルメディア配信 |
| `desktop/preload.cjs` | 最小限のIPCブリッジ |
| `ui/` | 日本語UI・Canvasグラフ・比較・試聴 |
| `analysis-version.json` | キャッシュ互換性を管理する共通バージョン |
| `mix_quality_visualizer_requirements.md` | 要件・算出案 |

モデル・ライブラリの背景は[Demucs](https://github.com/facebookresearch/demucs)、[pyloudnorm](https://github.com/csteinmetz1/pyloudnorm)、[Electron](https://www.electronjs.org/)を参照してください。配布用パッケージを作る際は、含める依存関係・モデルのライセンス表示を同梱します。
